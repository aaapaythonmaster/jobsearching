# 岗位右栏操作面板设计

## 目标

岗位工作区保持中间列表稳定，岗位的查看、HR 打招呼和简历调整都在右侧上下文栏完成；不再从列表跳转到中间详情页。

## 当前结构

- `frontend/src/modules/job-search/views/JobListView.vue` 渲染岗位筛选、岗位卡片和当前的“查看/删除”操作。
- `frontend/src/layouts/DefaultLayout.vue` 负责三栏壳层，但右栏只根据路由显示静态空态，展开按钮没有状态行为。
- `frontend/src/modules/job-search/views/JobDetailView.vue` 已包含岗位编辑、HR 打招呼和简历调整建议的完整 API 调用逻辑。
- `frontend/src/modules/job-search/api/index.ts` 已提供岗位详情、打招呼草稿、简历调整建议以及保存岗位所需 API，无需新增后端接口。

## 目标架构

- `DefaultLayout` 提供轻量的右栏上下文状态：当前岗位和当前面板模式（详情、打招呼、简历调整）。
- `JobListView` 通过共享的工作台上下文触发右栏模式，不再调用 `router.push` 进入详情路由。
- 新增 `WorkspaceContextPanel` 的岗位操作内容组件，复用 `JobDetailView` 的 API 逻辑，但将编辑和生成结果限制在右栏可滚动区域。
- 详情路由保留兼容性；岗位列表的操作不改变 URL，顶部不显示详情页返回按钮。

## 行为

1. 点击“查看”：中间岗位列表不变，右栏显示岗位基本信息和 JD 摘要。
2. 点击“打招呼”：右栏显示基础简历选择、生成按钮和历史草稿；生成和复制均在右栏完成。
3. 点击“简历调整”：右栏显示基础简历选择、生成按钮和历史调整建议；生成和复制均在右栏完成。
4. 点击右栏关闭/返回：清空当前右栏选择，恢复“选择一个岗位”的空态。
5. 点击删除：仍在列表中执行确认删除，不打开右栏。

## 非目标

- 不改后端 API、数据库或岗位详情返回结构。
- 不删除旧的 `/job-search/jobs/:id` 路由，避免已有链接失效。
- 不把整个中间列表重构成新的模块。

## 测试与验收

- JobListView 测试：操作按钮顺序为查看、打招呼、简历调整、删除；点击前三项不改变路由并发出右栏状态事件。
- DefaultLayout 测试：岗位右栏能根据共享状态渲染选中岗位和对应模式；无选择时显示空态。
- 运行前端测试、构建、`vibecoding-verify`，并在本地岗位页验证三种右栏模式。
